### Задание 1 **(2)**

*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*

**1.**
```cpp
int x = 10, y = 3;
std::cout << std::min(x = 15, x + y);
```

Вызовы аргументов `std::min` не задают порядок вычисления слева направо. В C++17 какой аргумент вычислится первым, не определено. Поэтому возможны разные результаты:

- если первым выполнится `x = 15`, второй аргумент станет `15 + 3 = 18`, результат — `15`;
- если первым вычислится `x + y`, он даст `13`, затем `x` станет `15`, результат — `13`.

**2.**
```cpp
int x = 10, y = 3;
x = 15, y += x, x += y;
```

Здесь запятые — оператор запятая, а не разделители аргументов. Он упорядочивает вычисления слева направо:

1. `x = 15` => `x = 15`;
2. `y += x` => `y = 3 + 15 = 18`;
3. `x += y` => `x = 15 + 18 = 33`.

Итог: `x == 33`, `y == 18`. Неоднозначности нет.

**3.**
```cpp
int x = 10, y = 9;
if (x > y++ && y++ > 9)
    std::cout << "yes" << endl;
std::cout << y;
```

Сначала сравнивается `10 > 9`: истина, после сравнения `y` увеличивается до `10`. Затем вычисляется правая часть `&&`: `10 > 9` — истина, после неё `y` становится `11`. Поэтому программа печатает:
```text
yes
11
```

Неоднозначности нет: `&&` вычисляется слева направо и не вычисляет правую часть только тогда, когда левая часть ложна.


Оператор запятая позволяет объединить выражения, сохранив их порядок:
```cpp
x += 1, z += 2 * x + 3 * y, y += 1;
```

C инкрементами:

```cpp

```

Во всех трёх вариантах сначала увеличивается `x`, затем `z` пересчитывается с уже увеличенным `x` и прежним `y`, после чего увеличивается `y`.

### Задание 9 **(3)**

```cpp
int i = 0;
std::vector<int> x(10);
std::cin >> i >> x[i];
std::cout << x[i];
```

Вычисление операндов может произойти до выполнения побочных действий.

До стандарта C++17 вычисление индекса `x[i]` может происходить до того, как первый оператор ввода записал новое значение в `i`. Тогда ввод, например, `3 42` может записать `42` в `x[0]`, а последующий вывод `x[3]` дает `0`. Такой код имеет неопределённое поведение, поэтому разные компиляторы или настройки могут давать разные результаты.

Начиная со стандарта C++17 вычисление ведется слева направо (вычисление операнда — выполнение побочного действия): сначала выполняется ввод в `i`, затем вычисляется `x[i]`. При корректном вводе `3 42` программа выводит `42`.

Из локальных версий стандартов языка C++ все сначала внести значение в перменную, потом прочли значение для массива. Из онлайн компиляторов нашелся компилятор `g++4.8.5`, который сначала вычислил все операнды, а потом уже выполнил побочные действия.

### Задание 1 **(2)**

**Пример 1. Цепочка сравнений**

```cpp
if (a < b < c) {
    // ...
}
```

В C++ это не означает "`a` меньше `b`, а `b` меньше `c`". Сначала вычисляется `a < b`, результатом становится `true` или `false`, затем это логическое значение сравнивается с `c`. Для проверки двух условий нужно написать:

```cpp
if (a < b && b < c) {
    // ...
}
```

**Пример 2. Неправильная граница из-за целочисленного деления**

```cpp
double middle = (a + b) / 2;
```

Если `a` и `b` имеют целочисленный тип, деление выполняется как целочисленное: дробная часть отбрасывается до присваивания в `double`. Например, при `a = 2` и `b = 3` получится `2.0`, а не `2.5`. Как надо:

```cpp
double middle = (a + b) / 2.0;
```

**Пример 3. Ошибка с отрицательным числом и остатком**

```cpp
if (n % 2 == 1) {
    // число нечётное
}
```

В C++ остаток от деления отрицательного числа может быть отрицательным: например, `-3 % 2` равно `-1`. Поэтому условие не распознает отрицательные нечётные числа. Надёжнее проверить:

```cpp
if (n % 2 != 0) {
    // число нечётное
}
```

Или вовсе:

```c++
if (n % 2) { ... }
```

**Пример 4. Ошибка из-за приоритета операторов**

```cpp
int x = 4;
if (x & 1 == 0)
    std::cout << "Чётное";
else
    std::cout << "Нечётное";
```

Программист предполагает, что сначала выполнится побитовое `&`, а затем сравнение с нулём. Однако оператор `==` имеет более высокий приоритет, чем `&`, поэтому выражение интерпретируется как `x & (1 == 0)`. Так как `1 == 0` ложно, результат сводится к `x & 0`, то есть к нулю. Программа выводит `Нечётное` даже для числа `4`.

Как нада:

```cpp
if ((x & 1) == 0)
    std::cout << "Чётное";
else
    std::cout << "Нечётное";
```

**Пример 5. Неправильное понимание тернарного оператора**

```cpp
int x = 5;
std::cout << x > 0 ? "Положительное" : "Неположительное";
```

Такой код не компилируется. Из-за приоритета операторов выражение разбирается не так, как предполагает программист: сначала выполняется операция вывода `x`, а затем результат пытаются сравнить с нулём. Поток вывода нельзя сравнивать с целым числом таким способом.

Правильный вариант:

```cpp
std::cout << (x > 0 ? "Положительное" : "Неположительное");
```

**Пример 6. Переполнение целого числа при умножении**

```cpp
int a = 50000;
int result = a * a;
std::cout << result;
```

Если результат умножения не помещается в диапазон значений типа `int`, возникает неопределённое поведение. Программа может вывести неожиданное значение. Чтобы избежать ошибки, можно использовать тип `long long`:

```cpp
long long a = 50000;
long long result = a * a;
std::cout << result;
```

**Пример 7. Использование логического И вместо побитового И**

```cpp
int x = 2;
int y = 4;

std::cout << (x && y) << '\n';
std::cout << (x & y) << '\n';
```

Операторы `&&` и `&` выполняют разные действия. Логический оператор `&&` проверяет, являются ли оба операнда ненулевыми, и возвращает `1` или `0`. Побитовый оператор `&` выполняет операцию над отдельными битами чисел. В данном примере первая строка выведет `1`, а вторая — `0`, поскольку двоичные представления чисел `2` и `4` не имеют общих установленных битов.


**Пример 8. Потеря значения из-за постфиксного инкремента**

```cpp
int x = 5;
int y = x++;
std::cout << x << " " << y;
```

Постфиксный инкремент `x++` возвращает старое значение переменной, а затем увеличивает её на единицу. Поэтому в `y` записывается `5`, а `x` становится равным `6`. Программа выводит `6 5`. Если программист ожидает, что `y` получит уже увеличенное значение, результат окажется неожиданным.

Если требуется сначала увеличить переменную, а затем использовать новое значение, следует применить префиксный инкремент:

```cpp
int x = 5;
int y = ++x;
std::cout << x << " " << y;
```

В этом случае программа выведет `6 6`.

**Пример 9. Путаница между присваиванием и сравнением**

```c++
int x = 5;
if (x = 0)
    std::cout << "Истина";
else
    std::cout << "Ложь";
```

Порой из-за опечаток в условии вместо оператора тождественности выходит оператор присваивания, и в таком виде код успешно компилируется, но работает не так, как надо. Во избежание подобных опечаток некоторые программисты пишут условия с литералами наоборот: сначала литерал, потом переменная, так код при опечатке не скомпилируется и явно укажет на ошибку.

```c++
int x = 5;
if (0 = x)
    std::cout << "Истина";
else
    std::cout << "Ложь";
```

**Пример 10. Неправильное вычисление параметров функции**

```c++
int x = 3;
f(x, ++x); // f() - something
```

Поскольку порядок вычисления параметров оператора `()` не определен, то может сначала вычислиться `++x`, а потом уже `x`, и выйдет, что в функцию подали два аргумента, равных `4`. Хотя программист может предполагать, что порядок вычисления идет слева-направо, и в итоге может получить неожиданный результат.

В таком случае лучше в принципе не изменять переменную `x` внутри скобок, лучше это сделать отдельно после выполнения функции, например, через оператор запятая:

```c++
int x = 3;
f(x, x + 1), ++x;
```

### Задание 3 **(10)**

Общая форма:
```cpp
condition ? expression1 : expression2
```

**1. Условие преобразуется к `bool`.** Если оно истинно, выбирается второе выражение, иначе — третье.
```cpp
int n = 7;
int result = (n != 0) ? 100 : 200; // result == 100
```

**2. Вычисляется только одна из двух ветвей.** Не выбранная ветвь и её побочные действия не выполняются.
```cpp
int x = 0;
int result = true ? 10 : ++x;
// result == 10, x == 0
```

**3. Если обе ветви имеют один тип и являются lvalue, результат тоже lvalue.** Поэтому через тернарный оператор можно выбрать объект для присваивания.
```cpp
int a = 1, b = 2;
(true ? a : b) = 9;
// a == 9, b == 2
```

**4. Если обе ветви — lvalue одного типа, но объект константный, результат сохраняет константность.** Присваивание через такой результат запрещено.
```cpp
const int a = 1;
int b = 2;
(true ? a : b) = 3; // ошибка: результат нельзя изменять
```
В этом примере общий тип ветвей — `int`, но из-за `a` результат условного выражения не даёт изменять выбранный объект.

**5. Если типы ветвей различаются, компилятор пытается привести их к совместимому общему типу.**
```cpp
int n = 1;
double value = n ? 2 : 3.5; // value == 2.0
```
Здесь целое число `2` преобразуется к `double`. Если подходящего общего типа нет, выражение некорректно:
```cpp
auto value = true ? 10 : "text"; // ошибка: несовместимые типы ветвей
```

**6. Ветви могут обе иметь тип `void`.**
```cpp
bool ok = true;
ok ? std::puts("готово") : std::puts("ошибка");
```
Обе ветви возвращают `void`, поэтому всё условное выражение также имеет тип `void`.

**7. Условный оператор может возвращать результат вызова функции, в том числе потоковую операцию.** Если типы результатов совместимы, выражение допустимо.
```cpp
bool ok = false;
ok ? (std::cout << "да") : (std::cout << "нет");
```
Будет выведено `нет`.

**8. Если одна ветвь — выражение `throw`, тип и категория результата определяются другой ветвью.**
```cpp
int n = 5;
int value = n > 0 ? n : throw std::runtime_error("n должен быть положительным");
```
При положительном `n` результатом будет `n`, иначе выполнение прервётся исключением.

**9. Условный оператор вычисляет условие первым, а затем — только выбранную ветвь.** Это удобно, когда вычисление одной ветви опасно или требует дополнительных ресурсов.
```cpp
int divisor = 0;
int value = divisor != 0 ? 100 / divisor : 0;
// value == 0; деления на ноль не происходит
```
